# @xyd-js/mcp

Model Context Protocol (MCP) tools and resources from an API definition, for servers built on the
MCP TypeScript SDK (`@modelcontextprotocol/sdk`).

- **tools**: one tool per REST operation of an OpenAPI document, generated by `uniformToMcpTools`
  (`@xyd-js/uniform`), which call the API when used;
- **resources**: one markdown reference page per operation (`api-reference://<name>`);
- **llms.txt**: the pages an `llms.txt` links to, as resources or behind a search tool.

ESM, Node 20+. `@modelcontextprotocol/sdk` and `zod` (3.25+ or 4) are peer dependencies.

## Tools

```ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { mcpUniformTools } from "@xyd-js/mcp";

const server = new McpServer({ name: "pets", version: "1.0.0" });
await mcpUniformTools(server, "./openapi.yaml", {
    readOnlyMode: true,
    headers: { "X-Api-Version": "2026-01-01" },
});
```

`mcpUniformTools` is two steps, which a server that builds an `McpServer` per request (a stateless
HTTP server) runs apart, so the document is read once:

```ts
import { mcpUniformToolDefinitions, registerMcpUniformTools } from "@xyd-js/mcp";

const tools = await mcpUniformToolDefinitions("./openapi.yaml", { limitCap: 50 }); // once
registerMcpUniformTools(server, tools, { maxBytes: 262144 }); // per server
```

`tools` is plain JSON (`McpTool[]`: `name`, `title`, `description`, `inputSchema`, `annotations`
and the HTTP `binding`), so it can also be generated at build time and loaded from a file. The source
may be a path or URL of an OpenAPI (`.json`, `.yaml`, `.yml`) or GraphQL document, or a `Reference[]`
already converted. Only REST operations become tools.

### What the tools are

- **name**: the `operationId` verbatim when it is a valid tool name (`^[A-Za-z0-9_-]{1,128}$`), else a
  slug of it; `toolName` overrides it.
- **inputSchema**: flat by default — the path, query and JSON-body properties at the top level,
  `additionalProperties: false` (unless the request body declares itself open); `flatten: false` groups them under `pathParams`, `queryParams`,
  `headers`, `cookies` and `requestBody`. It is listed in `tools/list` exactly as generated.
- **annotations**: `readOnlyHint` (default `GET`, `HEAD`, `OPTIONS`, `TRACE`), `destructiveHint`
  (`DELETE`, `PUT`, `PATCH`), `idempotentHint` (the read-only methods, `PUT`, `DELETE`),
  `openWorldHint` (false); each overridable by a predicate over the reference (`readOnly`,
  `destructive`, `idempotent`, `openWorld`).
- **renamed inputs**: in the flat layout a query parameter or body property that shares an earlier
  input's name is renamed (`<name>_query`, `<name>_body`); the call sends it under its own name
  (`binding.inputs`).
- **operations**: those whose body, if any, has a JSON variant; `include` decides otherwise.

### Options

Generation (forwarded to `uniformToMcpTools`): `toolName`, `flatten`, `include` (which operations),
`readOnly` / `destructive` / `idempotent` / `openWorld`, `limitCap` (caps an integer `limit`
parameter), `descriptionChars`, `maxDepth`, `extras`.

Selection: `readOnlyMode` registers only the tools whose `readOnlyHint` is true; `filter(tool)` has
the last say (e.g. by `name` or `binding.group`).

Calls:

| Option | Default | |
|---|---|---|
| `token` | the request's bearer | a string (one bearer for every call) or `(extra) => token`; by default `extra.authInfo.token`, i.e. the `Authorization` bearer of the HTTP request that carried the call |
| `baseUrl` | the document's first server | the API base URL, joined with each operation's path |
| `headers` | — | extra request headers, fixed or `(tool, extra) => headers`; set over the defaults case-insensitively, so an `Accept` or `Content-Type` here wins; an undefined or null value is not sent |
| `maxBytes` | 262144 | the answer is cut after this many bytes, with a `[truncated: …]` marker |
| `errorBytes` | 8192 | bytes of an error body quoted in the tool error |
| `timeoutMs` | 30000 | the request is abandoned after this long |
| `queryArrays` | `"repeat"` | an array query parameter as `a=1&a=2`, or `"comma"`: `a=1,2` |
| `validate` | true | check the arguments against the input schema before calling |
| `resourceLink` | — | `(tool) => link`: a `resource_link` answered beside each result |
| `fetch` | global `fetch` | the fetch implementation |

A call reads its arguments by the tool's `binding.layout` (flat or grouped; never guessed from
property names, so a flat body field called `headers` stays in the body), sends `Accept:
application/json` (and `Content-Type: application/json` with a body) unless `headers` says
otherwise, the resolved bearer last, fills the path from the path parameters (each one plain segment, percent-encoded), clamps an integer `limit` to
the bounds its schema declares, and answers the response body as one text block. A non-2xx answer is
`isError: true` with the status and the first `errorBytes` of the body; invalid arguments, an
unreachable API, a timeout and a cancellation by the client (each said as such) are tool errors too,
and none of them names the token — a `token` or `headers` function that throws gives a generic error,
not its message.

A source of no supported kind, or a document that cannot be read, throws (`loadUniformSource`); a
source without REST operations is warned about, naming it.

`callMcpUniformTool(tool, args, options)` and `buildMcpToolRequest(tool, args)` are exported for
servers that register tools their own way.

### The input schema and zod

`McpServer.registerTool` takes a zod schema and lists it as JSON Schema. The generated JSON Schema
rides on a loose zod object through zod's `_zod.toJSONSchema` override (`jsonSchemaInput`), so
`tools/list` shows it as generated and no zod source is generated or evaluated; the arguments are
validated against the same JSON Schema with the SDK's Ajv validator.

## Resources and llms.txt

```ts
import { mcpUniformResources, mcpLLMsResources, mcpLLMsTools } from "@xyd-js/mcp";

await mcpUniformResources(server, "./openapi.yaml");
await mcpLLMsResources(server, "https://example.com/llms.txt");
await mcpLLMsTools(server, "https://example.com/llms.txt", process.env.OPENAI_API_KEY!);
```

These load on first use from optional peer dependencies, so a tools-only server does not install or
load them:

- `mcpUniformResources`: `@xyd-js/atlas`, `@xyd-js/components`, `react`, `react-dom`, `codehike`,
  `turndown`, `turndown-plugin-gfm`, `remark`, `remark-gfm`, `remark-stringify`, `unist-builder`
  (and `@xyd-js/native` for the native code highlighter, when present);
- `mcpLLMsResources` / `parseLLMsContent`: `unified`, `remark-parse`, `remark-gfm`, `remark-stringify`;
- `mcpLLMsTools`: those, plus `@langchain/core`, `@langchain/classic`, `@langchain/openai`,
  `@langchain/textsplitters`.

A missing one fails the call with the list of what to install.

pnpm --filter @xyd-js/mcp build   # tsup (ESM) + tsc declarations
